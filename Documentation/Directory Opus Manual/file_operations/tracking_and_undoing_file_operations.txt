~~Title: Tracking and Undoing File Operations ~~
<pageheader/>

There are two features in Opus that help you keep track of changes you have made to files and folders.

==Undo==

The **Undo** command can (usually) be used to undo the most recent action. Most actions can be undone - for example, if you rename a group of files incorrectly with a wildcard, you can undo the rename fairly easily. File deletes, however, can not be undone unless the delete was done to the recycle bin. You can find the **Undo** command in the **Edit** menu in a Lister (or press <kbd>Ctrl+Z</kbd>).

{{:media:13:undo_history.png?nolink|}} 

Opus maintains a history of undoable functions. From the **Undo List** sub-menu, you can see the ten most recent actions, and undo any of them by selecting it from the list. Selecting the **More...** command from that sub-menu displays the [[:basic_concepts:the_lister:utility_panel|Utility Panel]], showing the **Undo Log** page. This page displays a full list of undoable actions, and you can undo one, many or all actions from this page at the click of a button.

==Redo==

What happens when you undo an action can work in two ways, controlled by the **Sequential undo** option in [[:preferences:preferences_categories:file_operations:options|Preferences]].

  * When **Sequential undo** is turned off, a new undo entry is created at the top of the undo list to undo the undo. For example, if you rename a file, pressing <kbd>Ctrl+Z</kbd> would undo the rename. Pressing <kbd>Ctrl+Z</kbd> again would redo the rename.
  * When **Sequential undo** is turned on, undoing an operation no longer adds the undone action at the top of the undo list. Instead, it adds it to a separate "redo" list. This lets you undo multiple actions in sequence, and optionally redo them in reverse order if needed, using the `Undo REDO` command.

==File Log==

While the undo log only shows the most recent undoable actions in the current session, the file log** **maintains a persistent log of all file operations (undoable or not). You can access the **File Log** from the [[:basic_concepts:the_lister:utility_panel|Utility Panel]], or select the command directly from the **Help** menu.

By default the file log records the last 1000 file operations. You can see what sort of action occurred, the file involved, when it happened, and in the case of a copy or move, the destination folder.

{{:media:13:file_log_example.png?nolink|}}

The file log can be extremely useful at times - if you've ever found that a file you knew was there has mysteriously disappeared, you can often find out what happened to it through the log. You can use the filter field to search for a file by name or path.

The **Save** button at the top of the log lets you export the log as a text file - useful if it's quite large and you want to search it in a text editor. You can configure the maximum size of the log, and control which operations are recorded, from the **[[:preferences:preferences_categories:file_operations:logging|File Operations / Logging]]** page in Preferences.
